| --- | --- | --- | --- |
| SR_01 | 원격 관절 제어 기능 | 사용자가 지정한 각도로 각 관절을 이동시킨다. 제어 대상 6축 (shoulder_pan / shoulder_lift / elbow_flex / wrist_flex / wrist_roll / gripper) 각도 지령을 −100\~100 정규화 값으로 변환하여 전송한다. 지령 주기 10 Hz | R |
| SR_02 | 실시간 자세 동기화 기능 | 실물 로봇의 현재 각도를 읽어 화면 모델에 반영한다. 폴링 주기 30 Hz 실물 → 시뮬 방향을 기준으로 삼는다. 연결 직후에는 실물 자세를 먼저 읽어 모델을 맞춘다. | R |
| SR_03 | 이중 로봇 제어 기능 | 두 대의 로봇을 하나의 화면에서 제어한다. 제어 방식 독립 / 미러 채널 선택 로봇1 사용 / 로봇2 사용 두 축은 서로 독립적으로 설정할 수 있다. | R |
| SR_04 | 비상 정지 기능 | 사용자 명령 시 모든 로봇을 즉시 현재 자세에 고정한다. 입력 수단 화면 버튼 / ESC 키 정지 중에는 모든 조작 입력을 차단한다. 토크는 해제하지 않는다. (해제 시 중력으로 낙하) | R |
| SR_05 | 동작 속도 제한 기능 | 목표 각도로 한 번에 이동하지 않고 속도를 제한하여 접근한다. 관절 40 °/s 그리퍼 60 %/s 급가속으로 인한 진동과 모터 과열을 방지한다. | R |
| SR_06 | 가동범위 제한 기능 | 각 관절이 기구적 한계를 넘지 않도록 지령을 제한한다. 제한 계층 소프트웨어 소프트 리밋 URDF 관절 리밋 모터 펌웨어 위치 리밋 상위 계층이 실패해도 하위 계층이 차단한다. | R |

| SR_08 | 모션 녹화 기능 | 로봇의 동작을 시간과 함께 기록한다. 기록 항목 경과 시간 6축 각도 그리퍼 개도 원본은 실물에서 읽은 각도로 한다. 지령값이 아니다. | R |
| SR_09 | 모션 재생 기능 | 기록한 동작을 원래 속도로 재현한다. 재생 속도 0.1 \~ 1.5 배 반복 재생 지원 재생 전 시작 자세로 먼저 이동한다. 비상 정지 시 재생을 중단한다. | R |
| SR_10 | 그리퍼 제어 기능 | 그리퍼의 열림 정도를 0\~100 %로 제어한다. 4절 링크 구조로 모터 1축이 손가락 2개를 대칭 구동한다. 모터 회전 140° ≈ 손가락 44° | R |
| SR_11 | 그리퍼 안전 기능 | 그리퍼가 기구적 한계를 넘지 않도록 차단한다. 실측한 양 끝단을 모터 펌웨어 위치 리밋에 기록한다. 양 끝에서 20 tick 여유를 둔다. 소프트웨어 오류 시에도 모터가 스스로 차단한다. | R |
| SR_12 | 상태 모니터링 기능 | 로봇의 현재 상태를 실시간으로 표시한다. 표시 정보 연결 상태 관절별 현재 각도 그리퍼 개도 제어 모드 비상 정지 여부 | R |
| SR_13 | 원점 캘리브레이션 기능 | 현재 자세를 각 관절의 0°로 재정의한다. 모터의 Homing_Offset 을 갱신한다. 갱신 직후 목표값을 현재 위치로 다시 기록하여 튐을 방지한다. 결과를 파일에 저장하여 재시작 후에도 유지한다. | R |
| SR_14 | 통신 복구 기능 | 통신 이상 발생 시 스스로 복구한다. 응답 대기 1 초 초과 시 재요청 연결 끊김 감지 시 자동 재연결 실물 자세를 읽기 전에는 지령을 내보내지 않는다. | R |

## 설계 판단 근거

**SR_04 — 왜 토크를 끄지 않는가**
12 V STS3215 는 토크를 끄면 팔이 중력으로 주저앉는다.
"멈춤"을 토크 해제로 구현하면 정지 명령이 곧 낙하 명령이 된다.
따라서 **현재 자세에 고정**하는 것이 이 시스템에서의 안전한 정지다.

**SR_07 — 왜 일부 관절만 토크를 끄는가**
STS3215 는 1:345 감속기라 역구동이 구조적으로 안 된다.
`Torque_Limit` 을 500 → 192 (38 %) 까지 낮춰도 손으로 꺾이지 않았다.
모터가 힘을 주지 않아도 기어 마찰이 남기 때문이다. 끄는 것 외에 방법이 없다.
다만 전부 끄면 팔이 주저앉으므로, **중력 모멘트가 없는 관절만** 끈다.

**SR_06 / SR_11 — 왜 제한을 3중으로 두는가**
소프트웨어 리밋은 코드 수정 한 번으로 무력화된다.
모터 펌웨어에 기록한 위치 리밋은 상위 소프트웨어가 잘못되어도 남는다.
사람의 실수를 마지막에 막는 것은 하드웨어여야 한다.

**SR_08 — 왜 지령값이 아니라 실측값을 기록하는가**
직접교시 중에는 지령이 발생하지 않는다. 실제로 일어난 일은 폴링으로 읽은 각도뿐이다.
지령값을 기록하면 손으로 가르친 동작이 통째로 비어 있게 된다.
